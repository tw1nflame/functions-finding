# Архитектура

```text
families (математика, ограничения, начальные приближения)
                         ↓
fit_family (NumPy lstsq / SciPy least_squares) → FitResult
                         ↑
ModelSelector (единое разбиение, оценка, выбор) → SelectionResult
                                                   ↓
                                            plot_fit → Figure
```

## Контракт семейства

`BaseFunctionFamily` не хранит обученные параметры. `name` и `parameter_names`
описывают модель; `evaluate` проверяет числовой домен и параметры и вызывает
`_evaluate`. Список параметров определяет число степеней свободы для выбора.
`parameter_bounds` задаёт границы, `initial_guesses` — детерминированные старты,
`formula` — числовую строку и LaTeX. Новые семейства подключаются передачей
экземпляра в селектор.

Опциональный `design_matrix` включает линейный подбор. У полиномов матрица
строится в координате `(x-center)/scale`; `linear_parameters` переводит решение
в коэффициенты степеней исходного `x` средствами `numpy.polynomial.Polynomial`.
Поэтому публичная формула не зависит от скрытой нормировки.

## Подбор параметров

`fit_family` проверяет массивы, достаточность различных значений `x` и домен.
Для линейной модели используется `numpy.linalg.lstsq` с проверкой ранга.
Для нелинейной — `scipy.optimize.least_squares(method="trf", x_scale="jac")`
с ограничениями. Невязки делятся на масштаб, вычисленный только по обучающему
`y`; множитель одинаков для всех наблюдений и не меняет задачу наименьших квадратов.

При нескольких стартах выбирается только **сошедшееся** решение с минимальной
обучающей суммой квадратов невязок. Число стартов и вычислений ограничено.
`nfev` суммирует сообщённое SciPy число вычислений для завершившихся попыток
(не включает вызовы для численного якобиана или оборванные исключением попытки).
Причины отказа стартов и ранг якобиана возвращаются как диагностика.
Неидентифицируемость не приравнивается к плохой точности кривой.

## Выбор и отсутствие утечки

`ModelSelector` создаёт разбиение один раз. Только `x[train]` и `y[train]`
передаются семействам для инициализации и оптимизации. Проверочные данные
используются для прогнозов и метрик уже обученной модели. У всех семейств
сохраняется один объект `SplitInfo` с исходными позициями строк.

- `random`: `sklearn.model_selection.train_test_split`.
- `group`: `GroupShuffleSplit` по кодам идентификаторов экспериментов.
- `time`: уникальные значения `x` сортируются; заданная доля последних значений
  идёт в проверку. Все строки с одной отметкой времени остаются вместе.

При одинаковом seed разбиение воспроизводимо. Нелинейные старты детерминированы
и seed не используют. Одинаковый запуск в одной программной среде воспроизводим;
между версиями BLAS/SciPy возможны небольшие численные отличия.

Кандидаты выбираются по минимуму проверочного RMSE с описанным в README допуском
простоты. Допуск отсчитывается от глобального минимума, а не последовательно от
соседних кандидатов. Число параметров, ошибка и исходный порядок задают однозначное
разрешение равенства. Кандидат, не сумевший предсказать проверочные данные,
исключается из выбора, но сохраняется с коэффициентами и диагностикой.

После выбора нет неявного переобучения. Чтобы обучить победившее семейство на всех
данных, вызывают `fit_family` отдельно; прежняя проверочная метрика не переносится
на новый результат как якобы заново измеренная.

## Результаты и визуализация

`FitResult` хранит семейство, коэффициенты, обучающие/проверочные метрики, успех и
диагностику. `SelectionResult` хранит все попытки, выбранный индекс и критерий.
Формулы и прогнозы вычисляются через соответствующее семейство. Массивы
коэффициентов и индексов защищены от случайной записи. Метрики и сами dataclass
объекты не предназначены для ручного изменения после обучения.

`plot_fit` — отдельный модуль: Matplotlib не импортируется основным API до
подключения визуализации. Она получает готовый результат, не обучает модели,
возвращает Figure и позволяет сохранить его в любом поддерживаемом формате.

## Ошибки и развитие

Общие некорректные данные и настройки дают понятное исключение. Ошибка одного
семейства перехватывается на границе попытки, чтобы продолжить сравнение; тип и
текст исключения сохраняются. Исключения остановки процесса не перехватываются.
Результат с неудачей всех кандидатов остаётся доступным для анализа.

Общий расчёт метрик выделен в `metrics.py`, проверка массивов — в `_validation.py`.
Глобального изменяемого состояния и собственного оптимизатора нет. Для будущей
прямой многомерной регрессии потребуется расширить контракт входных данных; одномерный API
намеренно отклоняет двумерный `x`. Слои оптимизации, результатов и визуализации
разделены, чтобы это изменение не требовало переписывать всё приложение.

## Второй этап: параметры как функции условий

В версии 0.2 добавлены независимые уровни `parameter_models/` и `multi_experiment/`.
Многомерные условия поддерживаются именно моделями коэффициентов; временные
семейства по-прежнему принимают одномерный аргумент.

```text
DataFrame → split_experiments → train / validation / test
                                  ↓
                           fit_trajectory → fit_family
                                  ↓
                    пригодные train-оценки theta_i
                                  ↓
              BaseParameterModel.fit(conditions, theta_i)
                                  ↓
           комбинации g → validation: f(t;g(z)) → выбор
                                                   ↓
                          MultiExperimentResult → test-оценка
```

Контракт временного семейства расширен необязательными возможностями:
`positive_parameters`, `requires_initial_value`, `with_initial_value` и `expression`.
Существующие числовые формулы и публичные сигнатуры не изменены.
`ExponentialRelaxationFamily` связывает наблюдаемое начало с отдельной копией
семейства для каждой траектории. Известные фиксированные коэффициенты реализованы
тонким адаптером, который передаёт только свободные параметры старому оптимизатору.

`BaseParameterModel` предоставляет fit/predict/formula/complexity. Встроенные
модели используют общий sklearn-код, а преобразование положительных целей хранится
в `ParameterRelationship`. Скалирование условий и все модели обучаются только на train.

`MultiExperimentResult` сохраняет индивидуальные подгонки, общую модель, диапазоны,
протокол и таблицы кандидатов. `CurveEvaluation` хранит прогнозы, покрытие и обе
агрегации метрик. Функции визуализации второго этапа импортируются отдельно и
не выполняют нового обучения. Подробности: [описание второго этапа](multi_experiment_regression.md).
