# Возможности и ограничения

## Какую задачу выбрать

| Данные и цель | Текущий API |
|---|---|
| Одна зависимость $y(x)$, сравнение формул | `ModelSelector` |
| Заданное семейство, нужны только коэффициенты | `fit_family` |
| Несколько временных кривых, условия постоянны внутри каждой | `MultiExperimentRegressor` |
| Два и более численных постоянных фактора | `condition_columns=["u", "v", ...]` |
| Несколько кривых одного независимого эксперимента | `group_column` + `trajectory_column` |
| Условия меняются во времени внутри кривой | Требуется другая модель; текущий API отклоняет такие данные |

## Если условия меняются во времени

Возможны две разные постановки. Они объясняют направления расширения и **не являются
реализованными возможностями** библиотеки.

**Мгновенный отклик:** результат определяется текущими условиями:

$$
\widehat y(t)=H\bigl(t,u(t),v(t);\boldsymbol\beta\bigr).
$$

Например, многомерная регрессия с признаками $t,u,v,tu,tv,uv$.
Её коэффициенты можно оценивать сразу по строкам наблюдений.

**Состояние зависит от истории:** результат накапливает влияние условий:

$$
\frac{dy}{dt}=G\bigl(t,y(t),u(t),v(t);\boldsymbol\beta\bigr),
\qquad y(t_0)=y_0.
$$

Тогда при каждом пробном наборе коэффициентов нужно решать динамическую модель,
сравнивать её траекторию с измерениями и минимизировать ошибку.
Для прогноза также нужна будущая траектория входов $u,v$ или сценарий её изменения.

Подмена меняющихся условий их средними в общем случае не решает ни одну из этих задач.
Если условия во всех экспериментах жёстко связаны со временем и друг с другом,
их отдельные эффекты могут быть неидентифицируемы даже при хорошем качестве fit.

## Границы версии 0.2

- Временное семейство второго этапа задаётся явно.
- Нелинейная оптимизация локальная; несколько стартов не гарантируют глобальный минимум.
- Нет доверительных интервалов, mixed-effects моделей и учёта погрешности параметров первого этапа.
- Нет автоматического заполнения пропусков, удаления выбросов или refit на train+validation.
- Неуспешные кандидаты сохраняются в диагностике; проверяйте `success` перед прогнозом.
- Экстраполяция условий определяется относительно прямоугольного диапазона train,
  а не выпуклой оболочки; предупреждение не является оценкой точности.

Как строить честную проверку: [валидация](validation.md).
