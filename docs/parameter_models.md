# Модели коэффициентов

Каждый коэффициент временной функции получает отдельную модель `g(z)`. Реализации
находятся в `parameter_models/` и не зависят от конкретного временного семейства.

Специализированные однофакторные законы Arrhenius, Ratkowsky, Hill и Monod описаны
в [дополнительном каталоге](additional_families.md). Они включаются явно и не
расширяют стандартный Auto-поиск. Их ограничения на шкалу target имеют приоритет
над автоматическим выбором identity/log; явный конфликт настроек отклоняется.

## Поддерживаемые формы

Для `m` числовых факторов:

| Модель | Формула | Число оцениваемых коэффициентов |
|---|---|---|
| `ConstantParameterModel()` | `a0` | 1 |
| `LinearParameterModel()` | `a0 + sum(aj*zj)` | `1+m` |
| `PolynomialParameterModel(degree=2)` | Линейные члены, квадраты, попарные произведения | `1+2m+m*(m-1)/2` |
| `PolynomialParameterModel(interactions=False)` | Линейные члены и квадраты | `1+2m` |

Общий механизм использует `StandardScaler`, `PolynomialFeatures` и
`LinearRegression(fit_intercept=False)` из scikit-learn. Свободный член входит
в матрицу признаков один раз. Масштабирование обучается только на train-условиях.
Матрица проверяется на полный ранг; при коллинеарных или постоянных факторах
неидентифицируемая модель отклоняется. Auto может выбрать более простую модель.
Если нужно сохранить линейную зависимость по непостоянным факторам, исключите
из `condition_columns` факторы, которые постоянны во всех обучающих экспериментах.

Для `q` оцениваемых коэффициентов нужно не менее `q` независимых train-экспериментов
и полный ранг матрицы. Это технический минимум, а не статистическая гарантия.
Количество кадров не увеличивает это число. Несколько траекторий одного
эксперимента получают веса `1 / число_его_пригодных_траекторий`.

## Преобразования и ограничения

`BaseFunctionFamily.positive_parameters` задаёт имена строго положительных параметров.
Для них по умолчанию обучается `log(theta) = g(z)`, а прогноз равен `exp(g(z))`.
Встроенные спецификации: `k` у `ExponentialRelaxationFamily` и `K` у
`RationalSaturationFamily`. Остальные параметры по умолчанию не преобразуются.

Например, `b` у старого `ExponentialFamily` допускает любой знак, поэтому логарифм
к нему автоматически не применяется. `L` у логистики допускает **ноль**, поэтому
также не объявлен строго положительным; финальные прогнозы всё равно проверяются
по границам временного семейства. Отрицательное предсказание недопустимого параметра
не обрезается молча, а даёт диагностируемый отказ.

Явное управление:

```python
model = MultiExperimentRegressor(
    ExponentialRelaxationFamily(),
    parameter_transforms={"A": "identity", "k": "log"},
)
```

Поддерживаются только `identity` и `log`. Для `log` все пригодные оценки должны быть
строго положительными; траектории с нулём/отрицательной оценкой исключаются с
диагностикой. Истинное переполнение/исчезновение в ноль при обратной экспоненте
вызывает ошибку. Конечный прогноз должен удовлетворять и ограничениям семейства.

## Manual и Auto

Словарь моделей без явного режима включает Manual:

```python
from parametric_regression import (
    MultiExperimentRegressor,
    ExponentialFamily,
    ConstantParameterModel,
    LinearParameterModel,
    PolynomialParameterModel,
)

model = MultiExperimentRegressor(
    time_family=ExponentialFamily(),
    parameter_models={
        "a": LinearParameterModel(),
        "b": PolynomialParameterModel(degree=2, interactions=False),
        "c": ConstantParameterModel(),
    },
)
```

Manual требует модель или известное фиксированное значение для каждого параметра.
Auto по умолчанию сравнивает Constant, Linear и полный квадратный полином. Можно
передать свой список `parameter_candidates` или закрепить отдельные зависимости
через `parameter_models` с явным `parameter_selection="auto"`.

Модели коэффициентов обучаются на train один раз. Затем выполняется полный перебор
допустимых небольших комбинаций, который не меняет их коэффициенты. Максимум —
`max_combinations=81` по умолчанию (достаточно для четырёх параметров и трёх моделей).
Если после пропуска непригодных моделей комбинаций всё ещё больше лимита, результат
сообщает об этом. Поиск не обрезается в произвольном месте: уменьшите кандидатов,
закрепите некоторые зависимости или явно увеличьте лимит.

Оценивается **финальная кривая**, а не расстояние до оценённых коэффициентов:
`f(t; predicted_parameters)`. По умолчанию используется среднее RMSE независимых
validation-экспериментов. Для минимальной ошибки `r` допускаются комбинации с
`score <= r*(1+relative_tolerance)+absolute_tolerance`; среди них выбирается меньшее
общее число оцениваемых коэффициентов вторичного уровня, затем меньшая ошибка,
затем исходный порядок. Значения по умолчанию — 1% и `1e-8` в единицах отклика.
Абсолютный допуск нужен для численно почти точных синтетических зависимостей;
при очень малом масштабе отклика его следует уменьшить.

## Константа и известное фиксированное значение

`ConstantParameterModel()` оценивает общую константу по train-оценкам. Для
положительного параметра в логарифмическом масштабе это соответствует геометрическому,
а не арифметическому среднему физических коэффициентов.

Если коэффициент нельзя устойчиво оценить на отдельных кривых, предпочтительно
передать известное **физическое значение**:

```python
model = MultiExperimentRegressor(
    ExponentialRelaxationFamily(),
    fixed_parameters={"k": 0.12},
    parameter_models={"A": LinearParameterModel()},
)
```

Тогда `k` фиксируется и при подгонке каждой временной кривой, и в итоговой модели.
В общий оптимизатор передаются только свободные коэффициенты. Это может устранить
неидентифицируемость. Известное значение не считается оцениваемым коэффициентом.

`ConstantParameterModel(value=...)` также доступен как модель заданного значения
**в масштабе цели вторичного уровня**: при `log` это значение логарифма. Он не
фиксирует параметр на первом этапе. Для обычного использования известных физических
параметров рекомендуется `fixed_parameters`, чтобы не смешивать эти два смысла.

## Диагностика идентифицируемости

`fit_family` дополнительно возвращает `jacobian_rank` и `jacobian_condition`.
Перед оценкой обусловленности столбцы якобиана нормируются по длине, чтобы разные
единицы параметров не определяли порог сами по себе. У линейных моделей используется
их матрица подбора. В общую регрессию не включаются оценки с недостаточным рангом
или числом обусловленности выше `condition_threshold=1e8`.

Такой критерий обнаруживает многие плоские/вырожденные кривые и почти взаимозаменяемые
коэффициенты, но не является полноценным анализом неопределённости. Настройку порога
нельзя подбирать по test. Все исключения видны в `experiment_parameters` и `warnings`.

## Расширение

Новый класс наследует `BaseParameterModel` и реализует:

- `complexity(n_features)` — число оцениваемых коэффициентов (неотрицательный `int`).
- `fit(X, y, *, feature_names=None, sample_weight=None)` — только обучение по переданным
  данным с поддержкой весов; возвращает `self`.
- `predict(X)` — конечный одномерный массив с одним коэффициентом на строку условий.
- `formula(*, latex=False)` — правая часть явного выражения.

Опциональный атрибут `required_transform` задаёт обязательную шкалу `"identity"`
или `"log"`. По умолчанию `None`: сохраняется прежнее поведение. Преобразование
выполняет регрессор, модель не должна повторно логарифмировать входной target или
экспоненцировать log-прогноз. Обратное преобразование выполняет `ParameterRelationship`.

Экземпляр передаётся в `parameter_models` или `parameter_candidates`. Перед fitting
создаётся независимая копия, поэтому один шаблон можно использовать для нескольких
параметров. Код временных семейств, оптимизации и разбиения менять не требуется.

Справка используемых готовых компонентов:
[PolynomialFeatures](https://scikit-learn.org/stable/modules/generated/sklearn.preprocessing.PolynomialFeatures.html),
[LinearRegression](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.LinearRegression.html).
