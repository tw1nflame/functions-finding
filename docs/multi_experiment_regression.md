# Двухэтапная регрессия по экспериментам

## Постановка

Для траектории `i` наблюдаются время `t`, отклик `y` и постоянный вектор условий
`z_i`. Сначала оцениваются параметры выбранного временного семейства:

\[
y_i(t)=f(t;\theta_i),\qquad \theta_{ij}=g_j(z_i;\beta_j).
\]

Итоговая модель: `y(t,z) = f(t;g(z))`. Временное семейство задаётся явно;
подбор его структуры одновременно с зависимостями коэффициентов в версию 0.2
не входит. Старые `fit_family` и `ModelSelector` сохраняют прежний API и поведение.

## Таблица и идентификаторы

В `fit` нужно указать `time_column`, `target_column`, `group_column` и непустой
список `condition_columns`. Все условия и время — реальные числа. Число условий
не фиксировано. Имена столбцов могут быть произвольными.

`group_column` всегда означает **независимый эксперимент**. Если внутри эксперимента
есть несколько микроорганизмов, передайте `trajectory_column` с глобально уникальными
идентификаторами траекторий. Один ID траектории не может относиться к двум экспериментам.
Без `trajectory_column` одна группа считается одной траекторией.

Условия должны быть постоянными внутри каждой траектории. Изменение хотя бы одного
фактора вызывает `ValueError`: библиотека не усредняет динамические условия.
Некорректные имена столбцов, нечисловые типы и пропущенные ID также отклоняются.
NaN/Inf во времени, отклике или условиях конкретной траектории сохраняются в её
диагностике; такая траектория не используется для обучения второго этапа.

## Алгоритм

1. **До любого fitting** создаётся разбиение независимых экспериментов. Допустимы
   случайное групповое разбиение и заранее заданные метки train/validation/test.
2. Только для train-траекторий вызывается существующий `fit_family`.
3. Проверяются успех, ранг и число обусловленности якобиана. Непригодные оценки
   остаются в таблице, но исключаются из вторичной регрессии.
4. Для каждого коэффициента обучаются модели условий. При нескольких траекториях
   одного эксперимента их суммарный вес в регрессии коэффициентов равен единице.
5. В Auto комбинации моделей оцениваются на исходных `y` validation-экспериментов.
   Параметры их временных кривых **не подбираются**. По умолчанию выбирается минимум
   среднего по независимым экспериментам RMSE с предпочтением меньшего числа
   коэффициентов при близком качестве.
6. После выбора единственная общая модель оценивается на test. Ни выбор, ни
   переобучение по test не выполняются. Автоматического refit на train+validation нет.

## Начальное состояние и время

Новое семейство:

\[
y(t)=y_0+A(1-e^{-kt}),\quad t\geq0,\quad k>0.
\]

`A` может иметь любой знак. `y0` — наблюдаемый вход, а не свободный intercept и не
функция температуры. Для каждой траектории время сдвигается: `elapsed = t-min(t)`.
В таблице сохраняется `time_origin`. При прогнозе нужно передать **прошедшее время**.

По умолчанию `y0` берётся из самого раннего измерения. Если в этот момент есть
повторы, используется среднее только этих начальных измерений. Можно передать
`initial_values={trajectory_id: value}`; отсутствующие в словаре ID используют
наблюдаемое начало. Переданное значение относится к самому раннему времени данной
траектории. Неизвестные ID отклоняются. Если нужно моделировать начало до первой
измеренной точки, сначала следует согласовать данные с нужным началом наблюдения.

Для validation/test начальное измерение разрешено использовать как известный вход
новой траектории. Все точки `elapsed=0` исключаются из оценочных метрик: предсказание
самого входа не должно искусственно улучшать качество. Стандартные метрики
`fit_family` в таблице индивидуальных подгонок по-прежнему включают все переданные
ему обучающие точки; агрегированные отчёты второго этапа исключают начальные точки.

Для остальных семейств автоматический сдвиг времени не применяется, `initial_value`
не нужен. `ExponentialFamily` не меняет смысл и порядок своих коэффициентов.

## Пример API

```python
from parametric_regression import MultiExperimentRegressor, ExponentialRelaxationFamily

model = MultiExperimentRegressor(
    time_family=ExponentialRelaxationFamily(),
    parameter_selection="auto",
    random_state=42,
)
result = model.fit(
    df,
    time_column="time",
    target_column="response",
    group_column="experiment_id",
    condition_columns=["temperature", "pH"],
    # trajectory_column="organism_id",  # если есть связанные траектории
    # split_column="partition",         # если разбиение задано заранее
)
if not result.success:
    raise RuntimeError(result.message)

print(result.parameter_formulas)
print(result.formula)
print(result.metrics["test"]["experiment"])
predictions = result.predict(
    time=[0, 5, 10, 15, 20],
    conditions={"temperature": 25, "pH": 7},
    initial_value=1.10,
)
```

Для одной новой траектории словарь условий распространяется на весь массив времени.
Для произвольных комбинаций можно передать DataFrame условий с одной строкой на
каждое значение времени и массив `initial_value` той же длины. Однострочный DataFrame
также распространяется на все моменты. Ожидаются ровно обучающие имена факторов;
порядок столбцов DataFrame автоматически приводится к обучающему порядку.

`model.predict(...)` делегирует последнему результату; отдельного механизма прогноза
в регрессоре нет. `result.predict_parameters(conditions)` возвращает физические
значения всех коэффициентов в порядке `time_family.parameter_names`.

## Результаты и диагностика

| Поле | Содержимое |
|---|---|
| `time_family` | Выбранное пользователем временное семейство. |
| `parameter_models` | Словарь `имя → ParameterRelationship`; внутри `.model` и `.transform`. |
| `parameter_formulas`, `parameter_latex_formulas` | Выражения для физических коэффициентов. |
| `formula`, `latex_formula` | Полная формула с подстановкой выражений в `f`. |
| `experiment_parameters` | Все траектории: условия, параметры train, успех, сообщения, пригодность для второго этапа. |
| `train_fits` | `FitResult` по ID обучающих траекторий, включая неудачные попытки. |
| `parameter_candidates` | Успех/отказ каждой модели коэффициента и причина пропуска. |
| `candidate_scores` | Все рассмотренные комбинации и их ошибки на validation; test-метрик здесь нет. |
| `evaluations` | Подробные отчёты с предсказаниями, ошибками по экспериментам и отказами. |
| `metrics` | Сводка отчётов `train_curve_fit`, `train_general`, `validation`, `test`. |
| `parameter_metrics` | Диагностика прогнозов коэффициентов относительно оценок train-кривых. |
| `condition_ranges`, `training_conditions` | Диапазоны и сочетания условий пригодных обучающих траекторий. |
| `split_protocol` | Метод, seed, доли, таблица экспериментов и метка части для каждой исходной позиции строки. |
| `warnings`, `message` | Сводка исключений и результата выбора. |

В `experiment_parameters` условия названы `condition:temperature`, коэффициенты —
`param:A`, `param:k`: префиксы исключают коллизии произвольных названий столбцов.
`used_for_parameter_models` явно отмечает вошедшие во второй этап траектории.
У validation/test коэффициенты остаются NaN, а сообщение указывает, что fitting
не выполнялся. Это принципиальное свойство, а не отсутствие отчёта.

Известные истинные коэффициенты можно проверить отдельно:
`result.score_parameters(conditions, true_parameters)`, где второй DataFrame содержит
столбцы с именами коэффициентов в физических единицах. Строки сопоставляются по
позиции. Эта функция ничего не обучает и не меняет выбор.

Формулы сохраняют явные числовые константы центрирования и масштаба условий:
например, `A(T) = c0 + c1*((T-center)/scale)`. Это аналитическая формула в исходном
аргументе, эквивалентная раскрытому линейному/квадратичному выражению. Вызова `eval`
в библиотеке нет. Числа в строке округлены до 12 значащих цифр; `predict` использует
полную точность. При совпадении имени фактора с `t`/`y0` обозначение времени/начала
в формуле получает суффикс, чтобы не смешивать разные аргументы.

## Визуализация

```python
from parametric_regression.multi_experiment.visualization import (
    plot_experiments,
    plot_parameter_dependency,
    plot_new_trajectory,
    plot_prediction_comparison,
)

figure = plot_experiments(result, partition="train", max_trajectories=4)
figure = plot_parameter_dependency(result, "k", "temperature", reference_conditions={"pH": 7})
figure = plot_new_trajectory(
    result, [0, 5, 10, 20], {"temperature": 25, "pH": 7}, initial_value=1.1
)
figure = plot_prediction_comparison(result, partition="test")
```

Все функции возвращают Matplotlib Figure, ничего не переобучают и не вызывают
`show()`/`savefig()`. При нескольких факторах график зависимости параметра — **срез**
при фиксированных остальных условиях. По умолчанию используются их обучающие
медианы. Точки оценок показывают все наблюдавшиеся сочетания и не обязаны лежать
на кривой этого среза.

## Ограничения

- Нелинейный fitting локальный. Проверка ранга/обусловленности — диагностика локальной
  устойчивости, а не доказательство глобальной идентифицируемости.
- Оценённые на первом этапе коэффициенты считаются целями второго этапа; перенос
  их статистической неопределённости и совместная оптимизация по `y` не реализованы.
- При малом числе независимых экспериментов сложные модели пропускаются, а не
  обучаются на искусственно увеличенном числе кадров/траекторий.
- Факторы постоянны внутри траектории. Нет динамических условий, ОДУ,
  доверительных интервалов или автоматического выбора временного семейства.
- При заданном `y0` оценивается условный прогноз будущего, а не прогноз самого
  начального состояния. Шум начального измерения влияет на всю траекторию.
- Для нестабильных коэффициентов можно выбрать Constant либо задать известное
  физическое значение через `fixed_parameters`; подробнее в [моделях коэффициентов](parameter_models.md).

Запускаемые примеры: `examples/multi_experiment_usage.py` и
`examples/multi_experiment.ipynb`. Они генерируют данные самостоятельно.
